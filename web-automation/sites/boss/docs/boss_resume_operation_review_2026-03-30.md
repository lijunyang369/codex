## 操作过程复盘

### 阶段一：直接走页面控件

一开始采用的是常规 Web 自动化方式：

- 打开新增工作经历表单
- 填充文本字段
- 操作日期选择器
- 操作职位选择器

这个阶段成功做到的部分：

- 公司名称、部门、工作内容、工作业绩可以正常填入
- 在职时间 `2023-10` 到 `2026-03` 也成功选中

这个阶段失败的核心点：

- `职位名称` 不是普通输入框
- Boss 要求的不只是显示文本，而是内部标准职位类型状态
- 单纯填 input 值，前端校验不会通过

实际报错为：

- `请填写职位类型`

### 阶段二：分析前端组件结构

后续切换到组件级分析：

- 识别出页面是 Vue 组件驱动
- 找到工作经历表单组件
- 拿到 `formData`
- 拿到职位库、行业库、保存方法

关键发现：

- 工作经历组件内部维护 `formData.position`、`positionLv2`、`industrySource` 等字段
- 职位选择需要调用组件自己的 `handlePositionSelected`
- 行业选择需要调用组件自己的 `handleIndustrySelected`
- 真正保存不是前端表单提交，而是父组件的保存链路

### 阶段三：绕过不稳定 UI，直接走组件保存

最终采用的方法：

1. 直接写入工作经历组件的 `formData`
2. 调用组件内部方法设置行业和职位
3. 捕获父组件 `handleUpdate` 所需的描述对象
4. 直接调用父组件正式保存逻辑

这一版成功把工作经历写入到了在线简历中。

### 阶段四：证书处理

证书模块同样不是简单输入框。

最终采用的方法：

1. 打开证书弹窗
2. 找到证书弹窗组件
3. 将 `高德拉特TOC整体管理执行大师证书` 加入 `selectedTags`
4. 调用证书组件自己的保存方法

这一版成功把证书写入了在线简历。

### 阶段五：个人优势处理

个人优势模块也有自己的提交包装逻辑，内部还夹了一层 AI 排版入口。

最终采用的方法：

1. 直接更新优势表单的 `infoData.advantage`
2. 绕过中间 AI 排版步骤
3. 直接走父组件正式保存链路

这一版成功把新的“业务 + 产研 + TOC”版本写进简历数据。

## 本次遇到的关键卡点

### 1. Boss 不是简单表单站

表面上看是普通输入框，实际上很多字段都依赖：

- 内部组件状态
- 标准化编码
- 父组件保存链路

尤其是：

- 职位名称
- 行业
- 证书

### 2. UI 点击不稳定

存在以下问题：

- 弹窗关闭后仍残留退场中的遮罩层
- 继续点击时事件可能不生效
- 日期和职位这类受控组件不适合只靠 DOM 填值

### 3. 页面显示编码异常

通过当前这套自动化链路读取中文时，部分文本会出现 `????` 形式的显示异常。

影响：

- 不影响实际写入和页面保存
- 会影响自动化检查时的可读性

当前判断：

- 这是自动化读取链路的编码呈现问题
- 不是 Boss 页面真实保存失败

### 4. Boss 内部还会给出“内容需继续完善”的提示

即使内容已经保存成功，页面仍然可能出现：

- `发现你的这段内容需继续完善，快去补充吧`

这类提示更像站内质量评分或启发式提示，不等于保存失败。

## 结论

这次 Boss 操作的经验可以归纳为：

- 普通文本项可以按常规方式处理
- 标准职位、行业、证书这类字段要优先考虑组件状态
- 如果 UI 不稳定，直接走组件和父级保存链路更可靠

后面再做 Boss 自动化时，优先策略应是：

- 先判断字段是不是标准化受控字段
- 能走组件方法就不硬点 UI
- 真正保存时优先复用父组件保存链路
