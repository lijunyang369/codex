# 共享协作区说明

## 1. 目的

`D:\Codex\shared` 是工作区级共享协作区，供多个线程之间同步背景、交接信息、审查结论和关键决策使用。

这个目录的目标不是替代项目文档，而是为多线程协同提供稳定、可复用、可追踪的共享上下文。

## 2. 适用场景

适合放入共享区的内容：

- 多线程都需要了解的当前阶段背景
- 架构、规范、环境方面的统一决策
- 审查结论和整改要求
- 线程交接材料
- 通用模板

不适合放入共享区的内容：

- 项目源码
- 项目内正式实施文档
- 运行产物
- 临时测试截图
- 一次性调试脚本

原则上：

- 项目正式文档仍放在项目目录内
- 跨线程共识与共享上下文放在 `shared`

## 3. 目录说明

### `context`

用于存放共享背景信息。

适合内容：

- 当前阶段说明
- 当前重点任务
- 全局约束
- 关键前提条件

### `reviews`

用于存放共享审查信息。

适合内容：

- 当前提交审查总结
- 问题清单
- 整改建议
- 审查索引

### `decisions`

用于存放共享决策记录。

适合内容：

- 架构决策
- 环境决策
- 工具选型结论
- 规范决策

### `handoff`

用于存放线程交接材料。

适合内容：

- 当前进展
- 未完成事项
- 风险点
- 下一线程接手建议

### `templates`

用于存放可复用模板。

适合内容：

- review 模板
- handoff 模板
- 实施计划模板
- 决策记录模板

## 4. 协作规则

1. 共享区只存放可复用、可共享、可沉淀的信息。
2. 项目正式内容优先落到项目目录，再视需要在共享区建立索引或摘要。
3. 线程交接优先写文档，不依赖聊天上下文口头传递。
4. 审查结论应尽量同时具备：问题、影响、建议、下一步。
5. 临时抓取文件、截图、HTML 页面不得直接放入共享区根目录。

## 5. 与项目目录的关系

以 `dhxy2-automation` 为例：

- 项目内正式文档：`D:\Codex\dhxy2-automation\docs`
- 工作区共享协作：`D:\Codex\shared`

推荐做法：

- 项目专属正式结论写入项目 `docs`
- 需要跨线程共享的结论，在 `shared` 中建立索引或摘要

## 6. 当前建议

当前建议优先把以下内容逐步纳入共享区：

- 当前阶段背景
- 审查总结索引
- 线程交接说明
- 架构决策记录
