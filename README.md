# Codex 工作区说明

## 1. 目的

本目录是共享工作区根目录，用于统一管理活跃项目、通用规范、下载资料和历史归档。

`D:\Codex` 顶层必须保持简洁、可解释、可维护。除工作区级说明文件外，不应在顶层散落零散文件。

## 2. 顶层目录说明

### `D:\Codex\dhxy2-automation`

《大话西游2》自动化项目主目录。

用于存放：

- 项目源码
- 项目配置
- 项目资源
- 项目测试
- 项目文档
- 项目运行产物

不应放入与该项目无关的脚本或其他项目文件。

### `D:\Codex\web-automation`

Web 自动化相关项目目录。

用于存放：

- 站点级自动化代码
- Web 自动化公共能力
- Web 自动化文档

### `D:\Codex\standards`

工作区级通用规范目录，供多个项目共享。

用于存放：

- 代码规范
- 架构原则
- 项目结构规范
- 通用工程约定

当前已存在的基线文档：

- `D:\Codex\standards\global-coding-standards.md`

### `D:\Codex\downloads`

临时下载区。

用于存放：

- 安装包
- 下载的参考资料
- 待归类的外部资源

该目录不是长期存储区。文件用途明确后，应尽快迁移到对应项目目录或归档目录。

### `D:\Codex\archive`

历史资料和非活跃内容归档区。

用于存放：

- 过时的环境脚本
- 一次性实验文件
- 历史产物
- 不再适合放在顶层的杂项文件

归档内容默认不视为当前项目输入，除非明确恢复使用。

## 3. 工作区规则

1. `D:\Codex` 顶层原则上只放目录，以及像 `README.md` 这样的工作区级说明文件。
2. 新项目必须放入独立项目目录，不能直接散落在顶层。
3. 共享规范和模板必须放入 `standards`。
4. 临时下载内容必须放入 `downloads`。
5. 历史文件和非活跃材料必须放入 `archive`。
6. 运行产物不得直接落在工作区顶层。

## 4. 命名建议

- 项目目录名应体现完整范围，而不是某个临时子功能。
- 优先使用稳定、可复用的命名方式，例如 `*-automation`、`*-platform`、`*-service`、`*-tools`。
- 如果项目范围大于某一单点能力，不应使用过窄命名，例如只用 `battle` 表达整个自动化项目。

## 5. 当前工作区定位

当前工作区围绕以下几类内容组织：

- 通用规范
- 游戏自动化项目
- Web 自动化项目
- 历史归档区

后续新项目应继续遵守这套结构，而不是把零散文件直接丢到顶层。
